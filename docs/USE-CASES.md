# 识海 使用场景演示

> 五个真实故事，展示知识如何从「一闪而过」变成「持久资产」。

---

## 场景一：创业者的 90 天知识进化

### 人物
小李，30 岁，前大厂产品经理，辞职创业做 AI 教育。

### 痛点
> "我每天冒出 10 个想法，月底只剩 1 个还记得，而且记不清当时为什么觉得它好。"

创业者的知识是**高密度、高流失**的。想法→调研→决策→复盘，每个环节都需要前一步的积累，但传统笔记让这些环节断裂了。

### 解法：用 识海 的 Thought → View → Project → Content 四级进化链

### 操作步骤

**Day 1 — 捕捉想法（Thought）**
```
创建笔记：「AI 个性化学习路径」
标签：#idea #ai-education
来源：早上洗澡时想到的
内容：每个学生的学习路径应该由 AI 动态生成，不是固定课程表。
```

**Day 7 — 发酵成观点（View）**
```
[[AI 个性化学习路径]] — 前 7 天我做了这些：
- 读了 3 篇论文（用 BibTeX 导入）
- 采访了 2 位 K12 老师
- 画了一张竞品对比图

新笔记：「观点：AI 教育的核心不是内容分发，是认知诊断」
标签：#view #ai-education
链接：← [[AI 个性化学习路径]]
      → [[竞品分析-松鼠AI]]
      → [[认知诊断理论综述]]
```

**Day 30 — 落地为项目（Project）**
```
新笔记：「项目：WonderLearn MVP」
标签：#project #active
- 目标：验证「认知诊断+个性化路径」是否可行
- 里程碑：Demo Day 在 Day 60
- 关键假设：学生愿意接受 AI 推荐的非线性路径
链接：← [[观点：AI 教育的核心不是内容分发，是认知诊断]]
      → [[技术架构设计]]
      → [[用户访谈记录]]
```

**Day 90 — 产出内容（Content）**
```
新笔记：「文章：我如何用 90 天验证一个 AI 教育假设」
标签：#content #published
Dataview 查询：所有 #ai-education 标签的笔记，按时间排序
→ 自动生成 90 天知识演化图
→ 文章引用了 Day1 的原始想法、Day7 的观点、Day30 的项目数据
```

### 链路图

```
Day 1          Day 7           Day 30          Day 90
┌──────┐      ┌──────┐       ┌──────┐       ┌──────┐
│Thought│─────→│ View │──────→│Project│──────→│Content│
│想法   │      │观点   │       │项目   │       │文章   │
└──────┘      └──────┘       └──────┘       └──────┘
  #idea         #view         #project       #content
   │             │              │              │
   └── 双向链接 ──┴── 双向链接 ──┴── 双向链接 ──┘
```

### 价值
- **不丢失任何一个想法**：Thought 捕捉零成本
- **想法会生长**：每一步都建立在前一步的基础上
- **90 天后自动复盘**：Dataview 一键生成知识演化报告
- **写文章 = 回顾 + 整理**：内容创作不再是痛苦的「从零开始」

## 场景二：投资者的知识复利

### 人物
王总，45 岁，二级市场投资者，年交易 200+ 笔。

### 痛点
> "我 3 年前看过一份研报，结论现在被验证了，但我死活找不到当时那个笔记。更可怕的是，我不记得自己当时是怎么想的。"

投资者的决策依赖**历史推理链**。单条笔记没用，重要的是「当时为什么这么判断」。

### 解法：研报 → 观点 → 决策链 → 回顾验证

### 操作步骤

**Step 1 — 收集研报（Source）**
```
笔记：「高盛 2025Q1 新能源报告」
标签：#source #research-report #new-energy
内容：核心结论、关键数据、图表截图
BibTeX：自动生成引用
```

**Step 2 — 提炼观点（View）**
```
笔记：「观点：锂电产能过剩将在 2025H2 见底」
标签：#view #new-energy
推理过程：
1. 高盛报告 → 产能利用率降至 65%
2. 碳酸锂价格 → 已跌至 7 万/吨（成本线附近）
3. 中小厂退出 → 产能自然出清
链接：← [[高盛 2025Q1 新能源报告]]
      ← [[碳酸锂价格跟踪]]
```

**Step 3 — 记录决策（Decision Chain）**
```
笔记：「决策：加仓宁德时代」
标签：#decision #new-energy #action
日期：2025-06-15
仓位：5%
理由：基于 [[观点：锂电产能过剩将在 2025H2 见底]]
风险：如果需求端继续下滑，产能出清会延后
止盈/止损：+30% / -15%
```

**Step 4 — 回顾验证（Review）**
```
Dataview 查询：
TABLE decision-date, outcome, return-pct
FROM #decision
WHERE contains(tags, "#new-energy")
SORT decision-date DESC

6 个月后回顾：
- 决策正确 / 错误？
- 哪些假设被验证 / 证伪？
- 我的判断模式有什么规律？
```

### 链路图

```
研报/数据          观点             决策链           回顾验证
┌──────┐        ┌──────┐        ┌──────┐        ┌──────┐
│Source │───────→│ View │───────→│Decision│──────→│Review │
│研报   │        │观点   │        │决策    │        │复盘   │
└──────┘        └──────┘        └──────┘        └──────┘
                  ↑                                │
                  └──────── 反馈修正 ──────────────┘
```

### 价值
- **决策可追溯**：每一笔交易都能回溯到原始推理链
- **避免重复犯错**：Dataview 统计「哪些类型的判断我总是错」
- **知识复利**：3 年后的观点建立在 3 年的验证之上
- **情绪脱敏**：写下推理过程本身就是冷静剂

## 场景三：研究员的文献网络

### 人物
张博，28 岁，计算机系博士在读，研究方向：大模型对齐。

### 痛点
> "我的 Zotero 里有 500 篇论文，但我只精读过 50 篇。写综述的时候，我根本记不清哪篇论文的哪个观点和哪篇论文有关系。"

研究员需要的不是「存储论文」，而是**构建论文之间的语义网络**。

### 解法：论文 → 页面 → 双向链接 → Dataview → 文献综述

### 操作步骤

**Step 1 — 导入论文（BibTeX）**
```yaml
# 在 识海 中导入 .bib 文件
# 自动生成：
- 标题页：「Constitutional AI (Bai et al., 2022)」
- 元数据：作者、年份、期刊、DOI
- 标签：自动提取 #alignment #constitutional-ai #anthropic
```

**Step 2 — 创建阅读笔记（Page）**
```markdown
# Constitutional AI 阅读笔记

## 核心方法
用一组「宪法原则」让 AI 自我批评和修正，减少 RLHF 依赖。

## 与我的研究的关系
→ [[RLHF 的局限性]] — 本文是对 RLHF 的替代方案
→ [[自我对齐 Self-Alignment]] — 更激进的版本
← [[InstructGPT]] — RLHF 的代表作，本文的对比基线

## 关键数据
- Helpful 模型 vs RLHF：毒性降低 30%
- 无需人类标注（节省标注成本 ~$50K）
```

**Step 3 — 双向链接自然生长**
```
当你读了 30 篇论文后，知识网络长这样：

         ┌─ Constitutional AI
         │        ↕
RLHF ←───┼─ InstructGPT
         │        ↕
         └─ DPO ──→ Self-Play
              ↕
         Reward Hacking
```

**Step 4 — Dataview 查询**
```dataview
// 查询所有与「对齐」相关的论文，按年份排序
TABLE authors, year, rating
FROM #alignment
SORT year DESC

// 查询「我给了高分但还没写综述」的论文
TABLE title, rating
FROM #alignment AND #unread
WHERE rating >= 4
```

**Step 5 — 一键生成文献综述**
```
指令：「基于 #alignment 标签下所有笔记，生成文献综述大纲」

识海 输出：
1. RLHF 范式的起源与发展（2017-2022）
   - [[InstructGPT]], [[Anthropic RLHF]]
2. Constitutional AI：规则驱动的对齐（2022-2023）
   - [[Constitutional AI]], [[Self-Alignment]]
3. DPO 及其变体：绕过奖励模型（2023-2024）
   - [[DPO]], [[IPO]], [[KTO]]
4. 开放问题
   - [[Reward Hacking]], [[Goodhart's Law]]
```

### 链路图

```
BibTeX导入        阅读笔记         双向链接网络       Dataview查询      综述
┌──────┐        ┌──────┐        ┌──────┐         ┌──────┐       ┌──────┐
│论文  │───────→│页面  │───────→│网络  │────────→│查询  │──────→│综述  │
│元数据 │        │笔记   │        │图谱   │         │筛选   │       │大纲   │
└──────┘        └──────┘        └──────┘         └──────┘       └──────┘
```

### 价值
- **从 500 篇到 50 篇精读**：Dataview 帮你筛选高价值论文
- **关系可视化**：双向链接自动构建知识图谱
- **写综述 = 查询 + 整理**：不再是「翻箱倒柜找笔记」
- **毕业论文有据可查**：每个论点都能追溯到原始论文

## 场景四：内容创作者的热点捕获流水线

### 人物
小陈，26 岁，科技自媒体，粉丝 50 万，每周 3 篇文章。

### 痛点
> "热点 3 天就凉了，但我写一篇文章要 2 天。等我写完，热度早过了。而且很多选题都是拍脑袋，没有数据支撑。"

内容创作者需要的是**从信息洪流中快速筛选、提炼、产出**。

### 解法：Hermes 抓热点 → 提炼趋势 → 选题 → 文章

### 操作步骤

**Step 1 — Hermes Agent 自动抓热点（每日 8:00）**
```
Hermes 定时任务：
1. 抓取 HN / Twitter / 微博 / 知乎 热榜
2. 筛选与「AI」「科技」「创业」相关的条目
3. 自动生成热点摘要，存入 识海

笔记：「热点 2025-06-15：OpenAI 发布 GPT-5」
标签：#hotspot #ai #openai
摘要：GPT-5 发布，重点是多模态推理能力提升...
来源链接：[HN讨论](https://...)、[Twitter热议](https://...)
```

**Step 2 — 趋势提炼（每周汇总）**
```
指令：「汇总本周 #hotspot 标签，提炼 3 个趋势」

识海 + Hermes 输出：
趋势 1：多模态成为标配（本周 4 条热点相关）
趋势 2：开源模型追赶速度加快（本周 3 条）
趋势 3：AI 监管政策密集出台（本周 5 条）
```

**Step 3 — 选题决策**
```
笔记：「选题评估：GPT-5 深度解读」
标签：#topic-candidate
评分：
- 时效性：⭐⭐⭐⭐⭐（热点刚出）
- 深度空间：⭐⭐⭐⭐（技术细节多）
- 我的独特角度：⭐⭐⭐（太多人在写）
- 流量预估：⭐⭐⭐⭐
结论：先写，但要找到独特角度
链接：← [[热点 2025-06-15：OpenAI 发布 GPT-5]]
      ← [[观点：多模态是 2025 主旋律]]
```

**Step 4 — 文章产出**
```
笔记：「文章草稿：GPT-5 不只是更大——多模态推理的技术解析」
标签：#article #draft

大纲（自动生成）：
1. 引子：GPT-5 发布 24 小时后的舆论场
2. 技术解析：多模态推理到底意味着什么
3. 对比：GPT-4o vs GPT-5 的能力边界
4. 我的判断：这对行业意味着什么
5. 结尾：你该怎么用 GPT-5

引用的素材（自动聚合）：
- [[热点 2025-06-15：OpenAI 发布 GPT-5]]
- [[OpenAI 技术博客笔记]]
- [[多模态模型对比测试]]
```

### 链路图

```
Hermes 抓热点      趋势提炼         选题评估         文章产出
(每日自动)         (每周汇总)        (决策)          (写作)
┌──────┐         ┌──────┐        ┌──────┐        ┌──────┐
│Hotspot│────────→│Trend │───────→│Topic │───────→│Article│
│热点   │         │趋势   │        │选题   │        │文章   │
└──────┘         └──────┘        └──────┘        └──────┘
  ↑                                                  │
  └──────────── 反馈：哪类内容效果好 ────────────────┘
```

### 价值
- **热点不遗漏**：Hermes 7×24 候着，你睡着它在工作
- **选题有数据**：不再拍脑袋，趋势 + 评分驱动决策
- **写作 10x 提速**：素材自动聚合，大纲自动生成
- **内容复利**：3 个月后回看，你有一套完整的「科技趋势知识库」

## 场景五：团队的知识协作飞轮

### 人物
小团队，8 人，做 B2B SaaS 产品。

### 痛点
> "老员工离职，带走了一脑子经验。新人入职，前 2 周基本在问东问西。我们做过什么决策、为什么这么做、踩过什么坑——全在大家脑子里，不在文档里。"

团队知识的三大病：**记不住、找不到、传不下**。

### 解法：三个 Wiki 分区——work / learning / onboarding

### 操作步骤

**Wiki 1：wiki-work（工作记录）**
```
结构：
wiki-work/
├── decisions/          # 决策记录
│   ├── 2025-06-01-为什么选-PostgreSQL.md
│   ├── 2025-05-15-定价策略讨论.md
│   └── 2025-04-20-技术栈选型.md
├── retrospectives/     # 复盘
│   ├── 2025-Q2-复盘.md
│   └── 上线事故-2025-05-30.md
└── weekly/             # 周报
    └── 2025-W24.md

决策记录模板：
# 为什么选 PostgreSQL
日期：2025-06-01
参与者：张三、李四、王五
背景：需要选择主数据库
选项：PostgreSQL / MySQL / MongoDB
结论：PostgreSQL
理由：
1. JSONB 支持好，兼顾结构化和非结构化
2. 团队有 3 年使用经验
3. 社区活跃，扩展丰富
风险：运维人才较少，已安排培训
```

**Wiki 2：wiki-learning（知识沉淀）**
```
结构：
wiki-learning/
├── tech/               # 技术知识
│   ├── Kubernetes-最佳实践.md
│   └── React-状态管理对比.md
├── domain/             # 业务知识
│   ├── SaaS-定价模型.md
│   └── 客户成功-CS-方法论.md
└── external/           # 外部学习
    ├── 竞品分析-XXX.md
    └── 行业报告摘要.md

每篇笔记都带：
- 标签（方便 Dataview 查询）
- 双向链接（关联其他知识）
- 「最后更新」时间戳
```

**Wiki 3：新人入职指南**
```
# 👋 欢迎加入！新人入职指南

## 第 1 天：环境搭建
- [ ] 申请公司邮箱
- [ ] 安装开发环境 → [[开发环境搭建指南]]
- [ ] 了解产品 → [[产品介绍-5分钟版]]

## 第 1 周：了解业务
- [ ] 阅读 [[SaaS-定价模型]]
- [ ] 了解我们的客户画像 → [[目标客户分析]]
- [ ] 回顾 Q2 复盘 → [[2025-Q2-复盘]]

## 第 2 周：动手实践
- [ ] 完成新手任务 → [[新人任务列表]]
- [ ] 提交第一个 PR
- [ ] 在 wiki-learning 中写一篇学习笔记

## 常见问题
- Q：为什么我们用 PostgreSQL 不用 MySQL？
  A：见 [[2025-06-01-为什么选-PostgreSQL]]
- Q：产品定价怎么来的？
  A：见 [[2025-05-15-定价策略讨论]]
```

### 链路图

```
日常决策/讨论          知识沉淀           新人入职
┌──────┐           ┌──────┐          ┌──────┐
│wiki-work│────────→│wiki-learning│───→│入职指南│
│决策记录 │          │知识库    │          │学习路径│
└──────┘           └──────┘          └──────┘
     │                  ↑                  │
     └──── 链接 ────────┴──── 链接 ───────┘
           （决策引用知识，知识解释决策）
```

### 价值
- **决策可回溯**：「为什么这么做？」→ 翻 wiki-work 30 秒找到
- **知识不流失**：人走了，知识在 wiki 里
- **新人 2 周上手**：不是 2 周问问题，是 2 周读 wiki + 动手
- **组织学习力**：每做一件事，团队就变聪明一点
