## 二、逐一对比

### vs Karpathy's LLM Wiki

Karpathy 提出了核心理念：用 LLM 作为知识图谱的读写头。但这是一个**方法论**，不是完整框架。

| | Karpathy | 识海 |
|---|---|---|
| **形态** | Twitter 帖子/博客 | 完整框架+模板+工具链 |
| **结构** | 未定义 | 五域+6种模板+Schema |
| **AI 协作** | 单一 LLM | 多 Agent 协同 |
| **隐私** | 未涉及 | 三级分类嵌入架构 |
| **可复现性** | 需要自己摸索 | 开箱即用 |

**一句话：** Karpathy 画了蓝图，识海 盖了房子。

### vs Obsidian + AI 插件

Obsidian 的 AI 插件（Smart Connections、Copilot、Text Generator）是**编辑辅助工具**，识海 是**知识管理系统**。

| | Obsidian + AI | 识海 |
|---|---|---|
| **AI 角色** | 辅助（帮你写、帮你搜） | 驱动（帮你建、帮你维护） |
| **知识结构** | 用户自定义 | 五域 Schema 强制 |
| **链接** | 可选 | 强制双向 |
| **维护** | 全手动 | Agent 自动+手动 |
| **适合** | 个人自由笔记 | 结构化知识积累 |

**一句话：** Obsidian AI 插件让你写笔记更快，识海 让你的知识自动生长。

### vs Notion AI

| | Notion AI | 识海 |
|---|---|---|
| **数据位置** | Notion 云端 | 本地 Obsidian vault |
| **AI 绑定** | 绑定 Notion 平台 | 工具可替换 |
| **结构** | 数据库视图 | 五域+双向链接图谱 |
| **隐私** | 数据在第三方 | 数据在本地 |
| **协作** | 原生多人协作 | 单人+Agent |
| **适合** | 团队项目管理 | 个人深度知识管理 |

**一句话：** Notion AI 适合团队协作管理项目，识海 适合个人构建终身知识资产。

### vs Mem.ai

| | Mem.ai | 识海 |
|---|---|---|
| **组织方式** | AI 自动组织（流式） | 结构化五域 |
| **链接** | 无显式链接 | 强制双向链接 |
| **分类** | 自动标签 | 域+类型+隐私三级 |
| **导出** | 有限 | Markdown 通用 |
| **适合** | 快速记录不想分类 | 长期知识积累 |

**一句话：** Mem.ai 帮你省去分类的麻烦，识海 让分类本身成为知识增值的过程。

### vs Roam Research + AI

| | Roam + AI | 识海 |
|---|---|---|
| **核心** | 块引用图谱 | 域+双向链接+认知递进 |
| **AI** | 后加的插件 | 原生三层架构 |
| **隐私** | 数据在 Roam 服务器 | 本地优先 |
| **学习曲线** | 陡峭 | 中等（有模板） |
| **适合** | 学术研究笔记 | 全领域知识管理 |

**一句话：** Roam 的图谱更强，但 AI 和隐私不如 识海。

### vs Logseq + AI

| | Logseq + AI | 识海 |
|---|---|---|
| **核心** | 大纲式笔记+图谱 | 五域+模板+认知递进 |
| **AI** | 插件 | 多 Agent 协同 |
| **数据格式** | 本地 Markdown | 本地 Markdown |
| **隐私** | 本地 | 三级分类 |
| **适合** | 日记+研究笔记 | 系统化知识管理 |

**一句话：** Logseq 更轻量适合日常记录，识海 更系统适合长期积累。

### vs RAG 方案（LangChain / LlamaIndex）

RAG 是**技术方案**，不是知识管理系统。

| | RAG | 识海 |
|---|---|---|
| **本质** | 检索增强生成 | 知识管理框架 |
| **工作方式** | 查询时检索相关文档 | 构建时建立关联 |
| **知识状态** | 被动（等你问） | 主动（持续维护） |
| **结构** | 向量相似度 | 语义链接+域分类 |
| **适合** | 给已有文档加 AI | 从零构建知识体系 |

**一句话：** RAG 让你问已有文档，识海 让你构建值得被问的知识。

## 三、识海 独有特性

### 1. 认知递进模型

```
Thought → View → Strategy → Project → Content
想法       观点      策略        项目       内容
"我注意到" "我认为"  "我们应该"  "开始做"   "发出去"
```

其他工具没有模拟人类认知过程。识海 让知识从碎片自然生长为产出。

### 2. 隐私嵌入架构

```
L1 公开 🟢 → 任何云端模型
L2 内部 🟡 → 可信云端或本地
L3 私密 🔴 → 仅限本地模型
```

其他工具的隐私是事后补丁。识海 把隐私分级写进 Schema，Agent 自动选择模型。

### 3. 三层 AI 协作

```
触达层（Hermes）  → 碎片捕获、快速查询
深度层（Claude）  → 批量整理、交叉审计
存储层（Obsidian）→ 图谱可视化、手动编辑
```

其他工具只有一个 AI。识海 让不同 AI 各司其职。

### 4. 模板驱动

6 种标准化模板（Concept/Thought/View/Memo/Project/Investment），每种都有完整的 frontmatter 规范。

其他工具让你自由记录。识海 让记录本身标准化。

### 5. 强制双向链接

A→B 必须有 B→A，每个页面最少 2 条出链。

其他工具的链接是可选的。识海 把链接变成铁律。

### 6. 多 Agent 协同

```
Hermes → 碎片捕获 + 每日维护
Claude Code → 深度审计 + 批量处理
Codex → 自动化脚本
OpenClaw → 知识→内容转化
```

其他工具只用一个 AI。识海 构建了完整的 AI 工具链。

## 四、选择建议

| 你的情况 | 推荐方案 | 原因 |
|---------|----------|------|
| 只想要简单笔记 + AI 辅助 | Obsidian + AI 插件 | 轻量、灵活、无学习成本 |

| **深度知识管理 + AI** | **识海** | 结构化+AI驱动+隐私保护 |
| **隐私优先 + AI** | **识海** | 三级分类+本地优先 |
| **多 AI 工具协同** | **识海** | 唯一支持多Agent的框架 |
| **长期知识资产积累** | **识海** | 认知递进+双向链接+模板 |

## 五、诚实声明

识海 **不适合**的场景：

- ❌ 团队实时协作（选 Notion）
- ❌ 只想快速记笔记不想建结构（选 Mem.ai）
- ❌ 纯学术文献管理（选 Zotero + Roam）
- ❌ 不想用 Obsidian（框架强依赖 Obsidian）
- ❌ 不想用 AI Agent（可以纯手动，但价值减半）

我们相信：**没有最好的工具，只有最合适的工具。** 识海 是为那些想要系统化管理知识、愿意投入时间建结构、重视隐私的人设计的。
