# 数据分类与隐私框架

> 识海 数据隐私保护核心规范  
> 版本: 1.0 | 最后更新: 2026-05-10

## 概述

识海 采用三级数据分类体系，确保不同敏感度的知识数据在合适的计算环境中处理。基于"数据不出域"原则，将隐私保护嵌入知识管理的每一个环节。

## 分级定义

### L1 - 公开级 (绿色 🟢)

- **定义**: 可公开分享的信息，无隐私或商业风险
- **处理环境**: 任意云端模型（无需信任要求）
- **适用领域**: 学习笔记、创意探索（早期阶段）、时间线记录

### L2 - 内部级 (黄色 🟡)

- **定义**: 组织内部或个人内部信息，泄露可能造成不便
- **处理环境**: 可信云端模型或本地模型
- **适用领域**: 工作笔记、创意成果（成熟阶段）

### L3 - 私密级 (红色 🔴)

- **定义**: 高度敏感信息，泄露可能造成严重后果
- **处理环境**: 仅限本地模型，禁止任何云端传输
- **适用领域**: 个人隐私记录

## AI 模型层级

| 模型层级 | 处理能力 | 数据级别 | 典型模型 |
|---------|---------|---------|---------|
| Tier 1 - 顶级云端 | 最强推理 | L1 only | Claude 4, GPT-5 |
| Tier 2 - 可信云端 | 强推理 | L1, L2 | Claude 4 (企业版), Azure OpenAI |
| Tier 3 - 本地大模型 | 中等推理 | L1, L2, L3 | qwen3:8b, gemma3:12b |
| Tier 4 - 本地轻量 | 基础推理 | L1, L2, L3 | qwen3:4b, phi-3-mini |

## 处理规则矩阵

```
┌──────────┬──────────────┬──────────────┬──────────────┐
│ 数据级别  │ Tier 1 云端   │ Tier 2 可信   │ Tier 3 本地   │
├──────────┼──────────────┼──────────────┼──────────────┤
│ L1 公开   │ ✅ 允许       │ ✅ 允许       │ ✅ 允许       │
│ L2 内部   │ ❌ 禁止       │ ✅ 允许       │ ✅ 允许       │
│ L3 私密   │ ❌ 禁止       │ ❌ 禁止       │ ✅ 允许       │
└──────────┴──────────────┴──────────────┴──────────────┘
```

## 数据流规则

### 写入规则

1. 新内容默认继承其所属领域的分类级别
2. AI Agent 写入时必须在 frontmatter 中标注 `classification` 字段
3. 包含个人信息的内容自动升级为 L3

### 读取规则

1. AI Agent 读取数据前必须检查分类级别
2. 根据分类级别选择对应层级的模型进行处理
3. 跨领域查询时，取最高分类级别作为整体处理级别

### 传输规则

1. L1 数据可自由传输至任何 AI 服务
2. L2 数据仅传输至经过验证的可信 AI 服务
3. L3 数据禁止离开本地环境

## 领域映射

| 领域 | 默认级别 | 可升级场景 | 可降级场景 |
|-----|---------|-----------|-----------|
| 📚 学习 | L1 | 含付费课程内容 → L2 | - |
| 🎨 创意 | L1 (早期) / L2 (成熟) | 涉及商业机密 → L3 | 脱敏后发布 → L1 |
| 💼 工作 | L2 | 涉及薪酬/人事 → L3 | 脱敏后分享 → L1 |
| 🏠 个人 | L3 | 不可升级（已是最高） | 脱敏且本人确认后 → L2 |
| 📅 时间线 | L1 | 含敏感事件 → L2/L3 | - |

## 升级/降级规则

### 自动升级触发条件

- 内容包含身份证号、银行卡号、密码等 → 自动升级为 L3
- 内容提及公司内部项目代号 → 自动升级为 L2
- 内容涉及未公开的商业策略 → 自动升级为 L3

### 降级流程

```
1. 人工审核原始内容
2. 执行脱敏处理（移除/替换敏感信息）
3. 在 frontmatter 中记录:
   - classification: [新级别]
   - declassified_by: [操作人]
   - declassified_date: [日期]
   - declassified_reason: [原因]
4. 审计日志记录
```

## SCHEMA.md 配置

在知识库的 SCHEMA.md 中配置分类标签：

```yaml
classification:
  levels:
    - id: L1
      name: "公开"
      color: green
      icon: "🟢"
      allowed_providers: ["*"]
    - id: L2
      name: "内部"
      color: yellow
      icon: "🟡"
      allowed_providers: ["trusted-cloud", "local"]
    - id: L3
      name: "私密"
      color: red
      icon: "🔴"
      allowed_providers: ["local"]
  
  domain_defaults:
    learning: L1
    creative: L1
    work: L2
    personal: L3
    chronicles: L1
  
  auto_upgrade_rules:
    - pattern: "身份证|银行卡|密码|社保"
      target: L3
    - pattern: "内部项目|商业机密|薪酬"
      target: L2
```

## 审计清单

日常运营检查项：

- [ ] 所有笔记的 frontmatter 包含 `classification` 字段
- [ ] AI Agent 处理数据前验证分类级别
- [ ] L3 数据未出现在任何云端 API 调用日志中
- [ ] L2 数据仅传输至白名单中的可信服务
- [ ] 降级操作有完整的审批记录
- [ ] 自动升级规则覆盖最新的敏感词库
- [ ] 月度数据分类合规报告已生成

## 示例

### 示例 1: 正常分类

```yaml
---
title: "Transformer 架构学习笔记"
classification: L1
domain: learning
created: 2026-05-10
---
```

### 示例 2: 自动升级

```yaml
---
title: "Q2 薪资调整方案讨论"
classification: L2  # 涉及薪酬，自动升级
domain: work
created: 2026-05-10
auto_upgraded: true
upgrade_reason: "检测到关键词: 薪酬"
---
```

### 示例 3: 手动降级

```yaml
---
title: "项目复盘（脱敏版）"
classification: L1
domain: creative
created: 2026-05-10
declassified_by: user
declassified_date: 2026-05-10
declassified_reason: "已移除客户信息和项目代号，准备公开分享"
---
```

---

> **原则**: 宁可过度保护，不可疏忽泄露。数据分类是知识管理的底线保障。
